# AIGTD Reminders v0.6.0 测试计划

## 1. 测试版本

- 候选版本：`0.6.0 (20)`
- 升级基线：TestFlight `0.5.0 (19)`
- 主题：自然控制、安全执行、失败恢复与撤销

## 2. 测试前准备

1. Xcode 选择 `AIGTDReminders` scheme 和测试 iPhone。
2. Signing Team 选择 `SMARTEFFI PTE. LTD.`，编译安装 `0.6.0 (20)`。
3. 在 Agent 页确认模型连接可用，并授予完整 Reminders 权限。
4. 新建“0.6 验收”清单；测试任务统一以“0.6”开头。
5. 每个用例执行后在系统 Reminders 核对真实任务，不只看 Chat 文案和卡片。

## 3. 核心验收

### 用例 1：单任务直接创建

发送：`明天下午 3 点提醒我开 0.6 验收会`

通过：任务只创建一次，标题和时间正确；卡片保持在原位置并显示真实成功结果。

### 用例 2：多动作按钮确认

发送：`把 0.6 验收会改到下午 4 点，再提醒我下午 3 点半带资料`

通过：先出现一张待确认卡；确认前没有写入；点击“执行这个计划”后两项都正确完成。

### 用例 3：多动作文字确认

重新生成一份两项方案，然后发送：`就按这个来`

通过：执行当前会话唯一有效方案；结果与按钮确认一致，不重新猜测或生成第二份方案。

### 用例 4：取消待确认方案

生成方案后发送：`算了，不执行了`

通过：原卡片变为已取消；Reminders 不变化；随后发送“执行吧”不能再执行已取消方案。

### 用例 5：卡片调整与取消

生成方案后点击“调整”，输入：`第二条不要改`

通过：输入框立即获得焦点；生成的新方案不含第二项，旧卡失效。再生成方案并点击“取消”，结果同用例 4。

### 用例 6：修改方案时间

为三条任务生成排期后发送：`B 不要动，C 放到下周一上午 9 点`

通过：确认前无写入；新卡只展示最终方案；旧时间和旧调用不能执行。

### 用例 7：App 重启后文字确认

保留一张待确认卡，彻底结束 App 后重新打开并发送：`执行吧`

通过：恢复并执行同一方案；无重复创建或修改；外部状态变化时安全报告冲突。

### 用例 8：同名目标继续澄清

创建两条同名“0.6 同名安全”，时间不同，发送：`删除 0.6 同名安全`

通过：列出差异并要求更具体；两条都不删除；不能默认选第一条。

### 用例 9：部分失败分类与安全恢复

人工场景：生成三项修改计划，确认前在 Reminders 删除其中一项，再执行。

通过：其余项目可成功，已删除项目报告外部状态变化；原成功项不重复写入；因为 `notFound` 属于刷新后重新确认，不显示“重试失败项”。

自动场景：网络、超时、临时 EventKit 或通用工具执行错误只选择失败项重试，并复用原操作标识；已成功、无需修改和不可重试项均不执行。该分支由 `AgentRecoveryPlannerTests` 与协调器重试测试覆盖。

### 用例 10：创建后撤销

创建“0.6 撤销创建”，成功后点击“撤销”或发送：`撤销刚才的操作`

通过：任务被删除，原卡显示“已恢复”；不调用模型猜测历史操作。

### 用例 11：改期后撤销

把“0.6 撤销改期”从上午 9 点改到下午 4 点，再撤销。

通过：恢复到上午 9 点，标题、清单和其他字段不被改动。

### 用例 12：移动与完成后撤销

分别移动“0.6 撤销移动”和完成“0.6 撤销完成”，每次成功后立即撤销。

通过：移动任务回到原清单；完成任务恢复未完成；状态均来自真实 Reminders。

### 用例 13：批量逆序撤销

确认一份包含创建、修改和移动的多动作方案，再点击撤销。

通过：按正向相反顺序恢复；每项显示真实结果；部分冲突不掩盖其他结果。

### 用例 14：外部修改后拒绝撤销

执行改期后，在系统 Reminders 手动改标题或备注，再回到 AIGTD 撤销。

通过：AIGTD 显示任务已有变化且不覆盖外部修改；卡片提供查看清单入口。

### 用例 15：普通聊天不闪卡

发送：`我今天有点累，先不整理任务。`

通过：只有自然回复；从发送到结束都不出现 pending 或结果卡；Reminders 无变化。

## 10. 最短人工验收清单

自动化通过后只需执行以下 4 组人工流程，不再逐条重复全部 15 个用例：

1. 三任务方案调整：覆盖用例 6，确认旧卡失效、确认前零写入、确认后只执行新版保留项。
2. 待确认方案重启：覆盖用例 7，强制结束 App 后用文字确认，并核对系统 Reminders 无重复写入。
3. 同名澄清与部分失败：覆盖用例 8、9，确认不会擅选同名任务；外部删除需刷新后重新确认，瞬时错误才允许只重试失败项。
4. 撤销与普通聊天：抽查创建、改期、移动、完成、批量和外部冲突撤销，再发送普通聊天，确认全过程不闪执行卡且 Reminders 无变化。

人工流程与 TestFlight 覆盖升级均已通过，版本状态更新为 Released（TestFlight 内部测试）。
