## 2. 版本背景

`0.6.0` 已经完成结构化工具调用、多动作计划、自然确认、方案调整、失败恢复、安全撤销和同名任务澄清。当前主要问题不再是“能不能完成任务”，而是产品仍有明显的工程界面感：

- 对话正文、摘要和执行卡片容易重复；
- 输入框、键盘、流式回复和卡片更新会争夺滚动位置；
- 输入框弹出、增长和收起不够连贯；
- 任务页容易让用户误以为可以像 Reminders 一样直接操作；
- 面向普通用户的界面仍可能暴露模型、API、Prompt 和诊断概念；
- 语音入口没有形成成熟、可预期的长按交互；
- 助手身份、欢迎方式、文案和视觉语言尚未统一。

因此，`0.7.0` 不扩大智能规划范围，而是把现有能力打磨成面向普通用户的完整产品体验。

## 3. 版本目标

> 将 AIGTD 从“功能可用的聊天式任务执行器”升级为温暖、安静、可信赖的个人事务助理。

版本完成后，用户应当能够：

- 打开 App 后立即理解小满能做什么；
- 通过文字或语音自然表达事务目标；
- 清楚区分普通聊天、查询、待确认方案和真实执行结果；
- 在键盘开合、流式回复和卡片更新期间保持稳定的阅读位置；
- 从只读任务概览确认真实 Reminders 状态；
- 在不接触模型、密钥和调试配置的情况下使用产品提供的 AI 服务；
- 在大字体、VoiceOver、弱网和操作中断等情况下继续可靠使用。

## 4. 非目标

`0.7.0` 明确不包含：

- AI 主导的优先级、工时、依赖关系和工作负载规划；
- 每日计划、每周计划和主动事务建议；
- 自建任务数据库或完整任务编辑器；
- 标签、子任务、项目树等新的任务管理能力；
- 多会话、工作区或复杂人格系统；
- 长时间会议转写、语音消息和录音文件管理；
- 与本轮体验升级无关的大规模 Agent 协议重构。

智能规划能力延后到 `1.1.0` 或后续版本，在 `1.0.0` 正式发布收口后重新评估。

## 5. 产品原则

### 5.1 一个长期存在的助理

- App 名称继续使用 `AIGTD`。
- 助理默认名为“小满”。
- 产品只有一个长期存在的小满，不使用 ChatGPT 式多会话列表。
- 首次进入 Chat 不要求用户给助理起名字。
- 后续可以在设置中提供改名能力，但不是 `0.7.0` 的 P0 范围。

### 5.2 AI 理解语义，本地保证执行安全

- AI 负责理解目标、上下文、补充和话题切换。
- 本地状态负责唯一有效方案、版本、有效期、外部变化和安全确认。
- 任何语音输入都不能绕过删除、批量操作和目标歧义确认。
- 只有真实工具返回成功后，界面才能表达“已经完成”。

### 5.3 Apple 原生交互质量，AIGTD 独立视觉身份

- 使用系统手势、动态字号、无障碍和键盘行为。
- 不把任务页做成 Apple Reminders 的复制品。
- 不使用系统清单式复选框、加号、滑动完成和行内编辑暗示。
- 通过暖白、品牌蓝和小满杏橙色建立独立识别。

### 5.4 结果真实，状态连续

- 不用文字、摘要和卡片重复表达同一结果。
- 同一事务状态在同一位置原地更新。
- 临时状态不作为独立聊天记录长期保存。
- 失败必须保留用户已经输入的内容，并提供明确下一步。

## 6. 信息架构

### 6.1 主导航

公开版本只保留两个一级 Tab：

1. `AIGTD`
2. `任务`

当前 `Agent` 页面移出一级导航。

### 6.2 公开设置

普通用户设置只包含：

- 提醒事项权限；
- 语音权限；
- 助理偏好和长期记忆；
- 上下文与隐私；
- 关于与反馈。

以下内容不得出现在公开 Release 产品中：

- 模型选择；
- 接口地址；
- API Key；
- Prompt 编辑器；
- Agent 内部文档；
- 结构化工具调用信息；
- 诊断记录和原始错误。

这些能力只允许存在于 Debug/Internal 构建，并应通过编译条件或独立内部入口隔离，而不只是视觉隐藏。

### 6.3 AI 服务发布约束

- 普通用户默认使用 AIGTD 提供的 AI 服务。
- 生产密钥不得嵌入 iOS 客户端。
- 正式公开发布前必须通过 AIGTD 服务端完成鉴权、额度、限流、Prompt 版本和密钥管理。
- 服务不可用时，公开界面只显示用户可理解的恢复提示，不暴露模型和接口术语。
- AI 暂时不可用时，任务只读概览、权限和隐私设置仍可使用。

该服务端能力是公开发布依赖，但不扩大本轮任务理解和智能规划范围。

## 7. 首次体验与小满人格

### 7.1 新手引导

首次引导控制在两步：

1. 说明 AIGTD 的作用以及任务仍保存在 Apple Reminders；
2. 在明确用途后请求 Reminders 权限。

麦克风权限只在用户第一次使用语音时请求，不在首次启动时集中索取。

### 7.2 首次欢迎语

首次进入 Chat 时，小满主动发送：

> 你好，我是小满，你的 AIGTD 事务助理。你可以直接告诉我想记下、调整或整理什么。

欢迎语只出现一次，不在每次启动时重复。

### 7.3 小满的表达边界

- 亲近但克制，不卖萌、不暧昧；
- 使用自然的“你”，不称呼用户“哥哥”；
- 回复简洁、结果优先；
- 信息不足时明确指出缺少的对象、时间或清单；
- 不用“我先处理一下”掩盖尚未发生的操作；
- 不输出内部思考、JSON、模型、Schema 或工具名称；
- 普通聊天保留自然陪伴感，任务操作保持可靠和有边界。

## 8. Chat 内容与卡片规则

### 8.1 普通聊天

- 只显示自然文字；
- 不显示执行卡片；
- 不闪现“正在执行”状态；
- 不因为没有任务动作而显示失败。

### 8.2 任务查询

- 先给一句简短结论；
- 需要时展示可点击的只读任务列表；
- 不显示执行卡片；
- 点击任务进入只读详情或在 Reminders 中打开。

### 8.3 单个直接操作

- 使用一张紧凑结果卡；
- 自然结果、任务、时间、清单只表达一次；
- 支持时显示“撤销”；
- 不再额外显示重复的成功正文和摘要。

### 8.4 多动作或高风险操作

- 文字只用于解释原因、风险或澄清问题；
- 完整计划放在一张待确认卡中；
- 卡片提供“执行这个计划”“调整”和弱化的“取消”；
- 调整后生成新版本方案，旧方案失效；
- 卡片原地更新为执行中、成功、部分失败或撤销结果。

### 8.5 状态锚点

- 发送后约 `100ms` 尚无可见回复时，在固定位置显示“正在理解…”；
- 普通回复到达后，同一位置变成流式自然文字；
- 确认存在任务动作后，同一位置自然展开为卡片；
- 约 `1.5s` 仍无结果时，显示真实等待状态；
- 不提前展示虚假的执行卡片；
- 不通过删除旧视图、插入新视图完成状态切换。

建议过渡时长为 `180～240ms`；开启 Reduce Motion 后改为短淡入淡出。

## 9. Chat 丝滑交互专项

### 9.1 当前代码问题

当前 `ChatHomeView` 中存在多套互相竞争的滚动和布局驱动：

- 消息数量、键盘高度、输入焦点、Tab 切换和流式文本都可触发滚到底部；
- 流式文本每增长一个字符都会改变滚动签名并启动动画；
- 键盘收起时强制回到底部，打断用户阅读历史；
- 每个流式增量都会保存 SwiftData，引起查询和页面重新计算；
- 输入框高度同时经过 UIKit 同步测量、异步复测和 SwiftUI 动画；
- 卡片只做透明度动画，但插入和状态变化会突然改变消息行高度；
- Chat 主视图同时承担模型调用、持久化、视口、输入框、语音和卡片职责。

### 9.2 统一滚动所有权

新增独立的 `ChatViewportController` 或等价状态对象，只有它可以决定是否滚动。

至少包含以下用户状态：

- `followingLatest`：用户停留在底部，允许跟随新消息；
- `readingHistory`：用户主动上滑，禁止自动拉回底部；
- `keyboardTransition`：键盘开合过程中保持内容相对位置；
- `sending`：发送新消息后确保用户消息和首个反馈可见。

行为规则：

- 用户上滑离开底部后立即进入 `readingHistory`；
- 流式文本和卡片更新不得打断 `readingHistory`；
- 非底部状态显示轻量“回到最新”按钮；
- 用户点击该按钮或主动滚到底部后恢复跟随；
- 键盘弹出和收起时，不强制改变正在阅读的历史位置；
- 只有发送自己的新消息可以主动揭示新消息区域；
- 流式跟随使用无动画的小幅位置更新，不为每个 token 重启滚动动画。

项目目标为 iOS 18，可以优先使用 `scrollPosition`、滚动几何和滚动阶段 API，而不是依赖多组键盘通知和无条件 `scrollTo`。

### 9.3 输入框布局

- 继续使用 `safeAreaInset(edge: .bottom)` 承载输入区；
- 不再使用键盘高度通知重复驱动布局和滚动；
- 输入框采用单向高度计算，避免 SwiftUI 与 UIKit 相互回写；
- 支持 1～5 行平滑增长；
- 超过 5 行后输入框内部滚动；
- 高度只在实际行数变化时过渡，不随亚像素测量反复动画；
- 点击输入框一次必须可靠聚焦；
- 外层聊天背景点击和文本输入手势不得争夺第一次点击。

### 9.4 流式渲染

- 流式文本保存在轻量内存状态中；
- UI 按帧或节流更新，不为每个 token 写入 SwiftData；
- 最终回复完成后再持久化完整文本；
- 如需中途恢复，可按低频检查点持久化，而不是逐字符保存；
- 当前消息行保持稳定 ID；
- 历史消息和 ActionLog 不应在每个 token 到达时全量重新扫描和重绘。

### 9.5 卡片尺寸过渡

- 待确认、执行中和结果必须复用同一张卡片；
- 卡片状态、内容和高度在原位置过渡；
- 卡片出现时不能突然把当前阅读内容推出屏幕；
- 用户处于底部时，卡片增长可以保持底部可见；
- 用户阅读历史时，卡片增长不得改变当前可见锚点；
- 不使用人为等待时间仅为展示短暂 pending 状态。

### 9.6 代码结构

将当前体积过大的 Chat 页面至少拆分为：

- `ChatTimelineView`；
- `ChatViewportController`；
- `ChatComposerView`；
- `VoiceCaptureOverlay`；
- `ChatMessageRow`；
- `ActionStatusCard`；
- 独立的对话发送与流式展示状态对象。

视图只负责展示和用户事件，不继续承担完整模型编排和工具执行分支。

## 10. 输入框与语音交互

### 10.1 默认输入框

输入区结构：

- 左侧：语音图标；
- 中间：文字输入和长按区域；
- 右侧：存在可发送文字时显示发送按钮。

空状态提示统一为：

> 发消息或按住说话…

交互规则：

- 轻点输入区域：打开键盘并进入文字输入；
- 长按输入区域或左侧语音图标：进入语音录制；
- 不需要先切换到独立“语音模式”；
- 已有文字时，文字区域长按优先保留系统选择菜单，用户按住左侧语音入口追加语音；
- 文字草稿、语音草稿和发送使用同一个输入框。

### 10.2 长按录音界面

达到长按阈值后，从底部连贯展开录音层，展示：

- 实时识别的最近 1～2 行文字；
- 克制的音量波形；
- 录音时长；
- `松手转文字`；
- `上滑取消`。

录音开始和进入取消区域时分别提供轻量触觉反馈。

### 10.3 上滑取消

- 上滑超过阈值后，提示变为“松开取消”；
- 使用文字和弱红色共同表达取消状态；
- 滑回有效区域后恢复录音；
- 松手取消后恢复录音前草稿；
- 不保留临时识别文字，不发送，也不弹出多余通知。

### 10.4 正常松手

正常松手后：

1. 停止采集；
2. 保留可靠的实时文字；
3. 显示“正在整理…”；
4. 使用最终结果替换不稳定尾部；
5. 将文字放入输入框；
6. 自动回到普通文字输入形态；
7. 不自动打开键盘；
8. 不自动发送。

用户可以修改、追加语音或主动点击发送。

### 10.5 草稿合并

- 不覆盖已有草稿；
- 优先插入当前光标位置，无法可靠定位时追加到末尾；
- 自动补充必要空格和基础标点；
- 不使用模型在发送前重写用户语义；
- 失败和中断时保留录音前草稿以及可靠的部分识别结果。

### 10.6 时长与异常

- 接近最长录音时间时给出可见提示；
- 达到上限后自动结束并转成草稿，绝不自动发送；
- 过短或没有有效语音时提示“没有听清，再试一次”；
- 网络或音频中断时保留可靠文字；
- 切换 Tab、进入后台或来电时停止录音并保留可恢复草稿；
- 公开错误不显示语音服务商、协议和密钥信息。

## 11. 任务概览

### 11.1 产品定位

任务页定位为“AIGTD 任务概览”，用于查看小满所连接的 Apple Reminders 数据，不是第二套任务管理器。

页面顶部说明任务来自 Apple Reminders，并显示同步状态：

- 刚完成同步时显示“刚刚同步”；
- 随时间更新为“最新同步 x 秒前 / x 分钟前”；
- 不得出现“x 秒后”。

### 11.2 视觉与操作边界

任务使用 AIGTD 品牌卡片和分组，不使用系统提醒事项式行布局。

任务页不提供：

- 圆形完成复选框；
- 新建加号；
- 滑动完成或删除；
- 行内编辑；
- 直接修改时间、清单和完成状态。

任务行展示：

- 标题；
- 时间；
- 清单；
- 当前状态。

点击任务进入只读详情，提供：

- 主要操作“让小满调整”；
- 次要操作“在提醒事项中打开”。

“让小满调整”返回 Chat，并将当前任务作为明确上下文。

### 11.3 清单与任务顺序

- 清单尽量遵循 EventKit 返回的系统顺序；
- 没有任务的清单也必须显示；
- 不得按名称、任务数量或自定义类别擅自重排清单；
- 任务尽量保留系统返回顺序，不再默认按完成状态、日期和标题重新排序；
- EventKit 未公开 Reminders 手动拖拽顺序时，不承诺 100% 复刻系统顺序；
- 无法取得系统顺序时，采用稳定、可解释的兜底排序，并在界面明确显示排序方式。

## 12. 视觉系统

### 12.1 视觉方向

整体定位：

> 温暖、安静、可信赖的事务助理。

- 主背景使用柔和暖白，而不是纯白或大面积黑色；
- 品牌蓝用于用户消息和主要操作；
- 杏橙色用于小满身份和轻量状态点缀；
- 深色模式使用温暖深灰，不使用纯黑；
- 普通回复使用简洁自然文本或轻量白色气泡；
- 任务、方案和执行结果使用独立的 AIGTD 卡片语言；
- 通过留白、浅色底和字号层级替代重边框与复杂阴影；
- 不使用夸张 AI 光效、无意义弹跳和大面积渐变。

### 12.2 动效原则

- 动效只解释状态变化和空间关系；
- 页面、键盘、输入框和卡片过渡共享一致节奏；
- 连续流式内容不反复启动完整动画；
- 关键状态变化建议使用 `180～240ms` 的短过渡；
- Reduce Motion 下只保留必要淡入淡出。

## 13. 文案与状态反馈

### 13.1 文案原则

- 短、准、温和；
- 结果优先，不先描述内部过程；
- 信息不足时说明具体缺少什么；
- 不重复说“我来处理”“我先看一下”；
- 不把技术错误直接交给用户；
- 不在工具尚未成功时使用完成时态。

推荐：

> “开会”已经改到明天下午 3 点。

不推荐：

### 13.2 状态反馈

- 正在理解：轻量、固定位置；
- 等待确认：明确说明确认后才执行；
- 正在执行：原卡片更新，不额外发送重复消息；
- 成功：展示真实结果；
- 失败：展示实际失败项和下一步；
- 弱网等待：说明仍在处理且没有执行新的操作；
- 临时状态不作为独立历史消息长期保存。

## 14. 无障碍、触觉与容错

- 所有可点击目标至少 `44×44pt`；
- 支持 Dynamic Type，大字体下不截断任务和关键操作；
- 状态同时使用文字、图标和颜色表达；
- VoiceOver 可读出任务、时间、清单、状态和操作结果；
- VoiceOver 和 Switch Control 提供不依赖长按的“开始录音 / 结束录音”操作；
- Reduce Motion 下移除明显位移动画；
- 触觉只用于开始录音、进入取消区、发送、成功和失败等关键节点；
- 执行按钮点击后立即锁定，防止重复提交；
- 网络中断、页面切换和进入后台不能丢失文字草稿；
- 失败后保留原始输入和方案，提供重试或调整；
- 颜色不得成为唯一状态提示。

## 16. 验收矩阵

### 16.1 Chat 与滚动

1. 点击输入框一次即可聚焦。
2. 键盘弹出后，最后一条消息和输入框保持可见。
3. 用户上滑阅读历史后，流式回复不会将页面拉回底部。
4. 键盘交互收起时不强制滚到底部。
5. 点击“回到最新”后恢复自动跟随。
6. 1～5 行输入平滑增长，没有高度抖动。
7. 超过 5 行后只在输入框内部滚动。
8. 300 条历史消息下滚动、输入和流式回复仍保持顺畅。

### 16.2 回复与卡片

9. 普通聊天不显示或闪现执行卡片。
10. 查询只显示自然结论和只读任务列表。
11. 单动作只表达一次结果。
12. 多动作计划只对应一张待确认卡。
13. 卡片从待确认到结果始终使用同一位置和身份。
14. 卡片增长不会突然改变用户正在阅读的位置。
15. 工具失败时不会显示成功文案。
16. 调整、取消、执行和撤销均作用于当前有效方案。

### 16.3 语音

17. 空输入框显示“发消息或按住说话…”。
18. 轻点打开键盘，长按进入录音层。
19. 录音中可看到实时文字、波形和时长。
20. 上滑取消可靠恢复原草稿。
21. 松手后文字进入输入框但不发送。
22. 已有草稿时语音追加不会覆盖原文。
23. 识别失败和系统中断尽量保留可靠文字。
24. VoiceOver 可以完成开始、结束、编辑和发送。

### 16.4 任务、设置与引导

25. 任务页没有复选框、加号、滑动编辑和行内编辑暗示。
26. 点击任务可进入只读详情并选择“让小满调整”。
27. 空清单仍然显示。
28. 清单和任务不被自定义规则擅自重排。
29. 同步文案只显示“刚刚同步”或“x 秒前 / x 分钟前”。
30. Release 构建看不到模型、接口、API Key、Prompt 和诊断。
31. 首次进入 Chat 能看到一次小满欢迎语。
32. 麦克风权限只在第一次使用语音时请求。

### 16.5 兼容与安全回归

33. `0.6.0` 的创建、查询、修改、移动、完成、删除、排期、确认、调整、取消、部分失败和撤销全部通过。
34. 同名任务仍然先澄清，不擅自操作。
35. 外部修改冲突仍然阻止旧方案覆盖新状态。
36. 清除上下文和长期记忆不会删除聊天历史或 Reminders 任务。

## 17. 性能与质量验证

自动验证至少包含：

- `ChatViewportController` 状态和滚动决策单元测试；
- Composer 状态机和草稿保留测试；
- 语音手势、取消、最终草稿和中断恢复测试；
- 普通聊天无卡片、卡片原地更新和重复提交保护测试；
- 现有全部 XCTest 回归。

真机性能验证至少包含：

- Instruments Animation Hitches；
- SwiftUI 视图更新检查；
- Time Profiler 主线程尖峰检查；
- 300 条历史消息长列表；
- 长文本流式回复；
- 键盘连续开合和交互式收起；
- 卡片从待确认到终态的完整过渡。

不能只以“编译成功”或“测试进程退出码为 0”作为体验完成依据。

## 19. 版本完成定义

`0.7.0` 的完成不是“换了一套皮肤”，而是用户能够明显感受到：

- 小满身份清楚且表达自然；
- 输入、键盘、滚动和语音连续流畅；
- 普通聊天、查询和执行反馈不会混淆；
- 卡片表达真实结果而不是内部日志；
- 任务概览可确认、不可误操作；
- 设置和错误不暴露工程概念；
- 现有可靠执行能力没有回退。

达到以上标准后，项目进入 `1.0.0` 正式发布收口，不在 `0.7.x` 扩张智能规划能力。
